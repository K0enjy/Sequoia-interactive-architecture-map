Hierarchical AI Agent System — Interactive Architecture Map

🌲
Hierarchical Architecture
Three-tier tree structure: Director → Managers → Workers. Each agent operates within a focused context window, avoiding "lost in the middle" degradation.
🔍
Technology Scouting
The Director researches LSP servers, plugins, and MCP servers online before delegating. Every downstream agent spawns with optimal tooling via tool-manifest.json.
📝
CLAUDE.md Cascade
Three levels of coding standards: Global (project-wide) → Domain (frontend/backend) → Task (worker-specific). Enforces SOLID, YAGNI, KISS across all generated code.
🔄
Resume / Checkpoint
Interrupted mid-run? Sequoia can resume from the last completed task. Task-tree.json is the single source of truth — completed tasks are skipped on restart.
💰
Zero-Cost Mode
Dual execution mode: Anthropic API (pay-per-token) or Claude Code subprocess (uses Claude Pro plan at $0 marginal cost). Factory pattern auto-detects available mode.
🔀
Git-Integrated Workflow
Automatic branch-per-task, atomic commits after each task completion, and merge to main. The orchestrator manages all git operations — agents focus on code.
⚙️ Subprocess Mode (Recommended)
  • Uses Claude Pro plan via Claude Code CLI
  • $0 marginal cost per project
  • Agents spawn as claude subprocesses
  • Auto-detected when claude is in PATH
  • Classes: DirectorClaudeCode, MidLevelClaudeCode, WorkerClaudeCode
🌐 API Mode
  • Uses Anthropic API directly
  • Pay-per-token pricing
  • Agents call anthropic.Anthropic() client
  • Requires ANTHROPIC_API_KEY env var
  • Classes: DirectorAPI, MidLevelAPI, WorkerAPI
0
INPUT: PRD (Product Requirements Document)
User provides PRD
A JSON file containing:
  • Project objective and description
  • Desired tech stack
  • User stories and requirements
  • External services (GitHub, DB, etc.)
Orchestrator initializes
State machine transitions: INIT → DIRECTOR_RUNNING
  • Parses PRD via Pydantic model
  • Creates output directory structure
  • Detects execution mode (API or subprocess)
  • Supports --resume flag to skip director
1
DIRECTOR AGENT IMPLEMENTED
1.1 Analyze PRD
Reads the full PRD and identifies tech stack, scope, and complexity.
1.2 Technology Scouting
Researches online for each language/framework:
  • LSP servers (e.g., TypeScript → vtsls)
  • Expert plugins for each domain
  • MCP servers (GitHub, PostgreSQL, Figma)
  • Install commands and configuration
1.3 Generate Tool Manifest
Output: tool-manifest.json
  • TechStack with LSP install commands
  • GlobalTools (linters, formatters)
  • MCP server configuration
  • Per-agent tool assignment
1.4 Generate Global CLAUDE.md
Creates project-wide coding standards:
  • Naming conventions and code style
  • Git workflow rules
  • Testing requirements
  • Security guidelines
  • Tool manifest reference
1.5 Build Task Tree
Decomposes PRD into hierarchical tasks:
  • Frontend tasks (UI, state, API integration)
  • Backend tasks (API, auth, database)
  • Infrastructure (Docker, CI/CD)
  • Dependencies and priority ordering
1.6 Write Artifacts
Persists to disk:
  • state/task-tree.json — full task hierarchy
  • state/tool-manifest.json
  • workspace/CLAUDE.md
  • Orchestrator state → SPAWNING_AGENTS
2
ORCHESTRATOR → MID-LEVEL MANAGERS IMPLEMENTED
2.1 TaskGraph Resolution
Orchestrator builds a TaskGraph from the task tree:
  • find_ready_tasks() — pending + all deps met
  • Sequential execution in dependency order
  • Status tracking: pending → in_progress → completed
  • Deadlock and failure detection
2.2 Git Branch Per Task
For each ready task, the orchestrator:
  • Creates branch task/{task-id}
  • Assigns task to appropriate agent
  • Commits results on completion
  • Merges back to main
2.3 should_subdivide() Decision
Manager evaluates task complexity:
  • More than 3 acceptance criteria? → SUBDIVIDE
  • Description exceeds 500 chars? → SUBDIVIDE
  • If subdivide: creates subtasks, injects into TaskGraph
  • If not: develops directly as a Worker
2.4 Domain CLAUDE.md
If subdividing, the Manager generates domain-specific standards:
  • Frontend: component patterns, CSS methodology
  • Backend: API design, database patterns
  • Extends the Global CLAUDE.md from Director
2.5 Subtask Injection
Subdivided tasks flow back into the orchestrator loop:
  • New subtasks added to TaskGraph
  • Parent task marked as completed
  • Subtasks become eligible in next iteration
  • Task tree persisted to disk after each change
3
WORKERS (Code Execution) IMPLEMENTED
3.1 Receives Atomic Task
A well-scoped task (e.g., "Create contact form with validation")
3.2 CLAUDE.md Cascade
Worker receives the full standards chain:
  • Global CLAUDE.md (project-wide rules)
  • Domain CLAUDE.md (frontend/backend specific)
  • Task context (acceptance criteria, dependencies)
  • Built by build_claude_md_cascade()
3.3 Tool Configuration
From tool-manifest.json, the Worker gets:
  • LSP servers for the target language
  • Framework-specific plugins
  • MCP servers for external services
3.4 Code Implementation
The Worker writes production code:
  • Creates/modifies files in workspace/
  • Follows CLAUDE.md coding standards
  • Working directory: output_dir/workspace
3.5 Commit and Report
On completion:
  • Git commit on task branch
  • Merge to main via orchestrator
  • Returns WorkerResult (files created/modified)
  • Task status updated in task-tree.json
4
INTEGRATION AGENT PLANNED
4.1 Trigger
Activates when all subtasks of a parent are completed. Verifies cross-component compatibility.
4.2 Integration Testing
Runs verification across merged code:
  • End-to-end tests
  • API contract validation
  • Type checking across boundaries
4.3 Handle Results
If tests pass: mark integration complete. If tests fail: analyze failures and reassign fixes to appropriate Workers.

Agent Hierarchy Structure

Level 1: Director (Strategic)
🎯 Director Agent
Strategic Planning & Tech Scouting
• Extends BaseAgent → BaseDirector
• Tech scouting (LSP / Plugin / MCP)
• Generates tool-manifest.json
• Generates CLAUDE.md + task-tree.json
• Modes: DirectorAPI, DirectorClaudeCode
Level 2: Mid-Level Managers (Tactical)
🎨 Frontend Manager
Frontend Domain
• Extends BaseAgent → BaseMidLevel
• Domain CLAUDE.md (component patterns)
• Decide: develop vs subdivide
• Spawns UI, style, JS workers
⚙️ Backend Manager
Backend Domain
• Extends BaseAgent → BaseMidLevel
• Domain CLAUDE.md (API design, SOLID)
• Decide: develop vs subdivide
• Spawns API, DB, auth workers
🛠️ Infra Manager
Infrastructure Domain
• Extends BaseAgent → BaseMidLevel
• Domain CLAUDE.md (Docker, CI/CD)
• Often develops directly (small scope)
• Spawns Docker, config workers if needed
Level 3: Workers (Execution)
🎭 UI Worker
HTML / Components
• Extends BaseAgent → BaseWorker
• Atomic task: single component or page
• Reads full CLAUDE.md cascade
📊 Style Worker
CSS / Theming
• Extends BaseAgent → BaseWorker
• CSS variables, responsive design
• Theme toggle, animations
🔌 API Worker
Endpoints / Routes
• Extends BaseAgent → BaseWorker
• REST endpoints, validation
• Request/response models
🗄️ Database Worker
Schema / Queries
• Extends BaseAgent → BaseWorker
• Schema, migrations, CRUD
• Connection management
Orchestrator (Control Plane)
📊 Orchestrator
State Machine & Task Scheduling
• States: INIT → DIRECTOR_RUNNING → SPAWNING_AGENTS → MONITORING_TASKS → COMPLETE
• TaskGraph: dependency resolution, ready-task finding
• Git ops: branch, commit, merge per task
• Resume support: --resume skips Director
• Persists task-tree.json after every status change
